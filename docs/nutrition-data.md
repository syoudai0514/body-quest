# 食品検索・計算・保存の仕組み

## 検索と出典

「食事」→「食品・メーカーを探す」で登録食品と標準食品を検索します。全角・半角、ひらがな・カタカナ、SAVAS／ザバス、鶏胸／鶏むねなどを正規化し、複数の検索語をすべて含む候補を表示します。表示する件数は制限し、候補を選んでから食べた量を入力します。検索結果の詳細は折りたたみ、トップ画面に追加の一覧を出しません。

標準食品は[日本食品標準成分表（八訂）増補2023年・2026年3月27日訂正データ](https://www.mext.go.jp/a_menu/syokuhinseibun/mext_00001.html)から引用した2,537件です。可食部100gあたりのエネルギー、たんぱく質、脂質、炭水化物を使用し、アミノ酸組成によるたんぱく質・糖質・糖類と取り違えないよう列名を検査しています。微量を示すTrは0、括弧付き推定値は数値として扱い、4成分の欠測がある1件は推測せず除外します。出典・訂正日・元ファイルのSHA-256をJSONに保存します。標準値は個々の商品を測定した値ではありません。PWAキャッシュの取得後はオフラインでも検索できます。

市販品は「メーカー表示を検索」で明示的に検索します。明治の商品一覧・公式検索、キユーピーの公式検索、森永乳業のヨーグルト一覧を優先し、掲載された商品のリンクを取得します。対応する一覧とメーカーURLからの検索はGeminiキーやGoogleの検索枠を必要としません。それ以外の検索では、Google検索付きGeminiに商品名・容量・JAN等の検索語を送り、メーカー公式URLの候補だけを取得します。健康記録・体重・食事履歴はこの検索に送りません。公式検索・商品一覧の取得はメーカーへ、Google検索を使う場合はGoogleへ検索語を送ります。Google検索を使った場合は実際の検索メタデータを確認し、サーバーが対応メーカーのページを取得して、基準量と4成分が揃った栄養表・定義リスト・ラベル付きリストから数値を抽出します。AIが回答した栄養値は採用しません。対象URLとすべてのリダイレクトはHTTPS・メーカーの許可リストで検証します。検索語単位の15分キャッシュは最大100件で、個人記録は含みません。検索は既存の30回/時のインスタンス内制限とGoogle側の上限に従います。[Google検索のグラウンディング](https://ai.google.dev/gemini-api/docs/generate-content/google-search)はAPIの利用条件・料金に従います。

すべてのメーカー・ページ形式に対応するものではありません。画像だけの表示、JavaScriptで生成される表、範囲表示、基準量や成分が欠けた表は値を創作せず、出典・写真・手入力へ案内します。味・容量・たんぱく質量が違う商品は候補を区別し、手元の商品との一致は保存前に確認します。新しい容量のページを取れることと、旧パッケージの値が同じことは別です。

## 計算の基準

食品には「写真の表示値／メーカー表示／文科省の標準値／材料・完成重量／手入力／推定」の区分と、基準量・元の4成分・調理状態・出典URL・確認日を保存します。今回の栄養表示写真を最優先にし、登録・履歴との名前一致だけで置き換えません。古い保存形式で基準が不明な食品は、名称をAIへ渡しても栄養値を換算根拠として渡しません。矛盾した値と非表示の食品も数値参照から除きます。基準未確認・矛盾・非表示の食品は、たんぱく質を補う自動追加候補からも除き、誤った値の再利用を防ぎます。

計算は「元の基準値 × 食べた量 ÷ 基準量」に統一します。g・kg同士、ml同士、同じ単位の本・袋等を換算し、gとmlの変換や1皿の重量は推測しません。1/2本は半量として扱います。1本430mlを半分飲んだ場合、参照は1本のままで食事は215mlの値を保存します。途中で丸めず、表示だけを丸めるため、C18.5gの半量9.25gを全量に戻してもC18.5gです。ラベルのカロリーを4P+9F+4Cから再生成しません。

生・調理後の重量を分けます。自作料理は材料100gあたりの成分と使用量を合算し、「食べた完成重量／完成後の全体重量」で配分します。油・調味料も材料に含めます。材料の値・使用量・出典と完成重量を保存し、後から計算を追えるようにします。肉汁等への流出を実測する方法ではなく、取り分けの推定です。

## 食品の管理と過去の記録

「食品を管理」は要確認／使用中／非表示を切り替えます。以前の形式で根拠がない食品、PFCが重量を超える食品、保存値と基準値が矛盾する食品などを確認できます。食品の修正は次回の記録に使い、直前の名前・基準量・値・出典は最大10件の修正履歴に保存して戻せます。名称だけで同一商品と判定せず、調理状態・基準量・メーカーや標準値の出典URLも識別に使います。再検索で同じ食品を増殖させません。JANが取得されている場合はJANを識別に使います。

食事の記録には、その時点の値・分量・元の基準・出典を独立して保存します。登録食品を200kcalへ修正しても、昨日の193kcalの記録はそのままです。履歴から再追加・量の変更・バックアップ復元でもこの基準を保持します。間違った過去の食事を直す場合は、対象の食事記録を修正します。食品を非表示にしても過去の記録は消えず、食品リストへ戻せます。旧形式のバックアップも受け入れ、過去の量を推測して書き換えません。

## 標準データの再生成

Pythonとopenpyxlを用意し、公式の訂正版をダウンロードして実行します。元のExcelはリポジトリに含めません。

```bash
python -m pip install openpyxl
curl -L 'https://www.mext.go.jp/content/20260327-mxt_kagsei-mext-000029402_02.xlsx' -o /tmp/bodyquest-mext-foods.xlsx
python scripts/import-food-composition.py /tmp/bodyquest-mext-foods.xlsx
npm run build
```

列の変更・食品コードの重複・件数不足は変換時に停止します。更新時は欠測の除外一覧、代表的な生／調理後の値、引用表記と日付を確認します。新しい訂正版ではスクリプトのSOURCEと検査条件も見直してください。
