# 検証記録

実装時にNode.js 24 / Chromiumで確認。iPhone実機・Safari固有の動作は公開後に確認が必要。

## 成功した検証

- `npm run build`：TypeScript型検査、Vite本番ビルド、PWAサービスワーカー生成。
- 栄養・日付・バックアップのテスト7件とAPIのテスト2件：アルコール熱量、完成重量での配分、朝夜の分離、前週比較の記録日数、不正バックアップ拒否、期限計算、未設定時の拒否、認証・入力・AI応答・無料枠エラー。
- 実ブラウザ：390pxと320pxの幅で横スクロールなし。表示・操作中のJavaScriptエラーなし。
- ご飯1食234kcal、ハイボール3杯（ウイスキー各30ml、40%）約199kcalが食事に反映。
- リロード後も食事が残り、朝87.5kg・夜88.3kgを別記録、朝平均は87.5kg。
- 商品表示を100g単位で登録し、鶏肉・玉ねぎ・きのこ・ルーを完成重量で配分。100g単位でない食品は材料選択から除外。
- 痛みがある日のメニュー切替、運動の保存、目標・配慮設定の保存。
- JSONバックアップのダウンロードと復元。不正なバックアップは元の記録を壊さず拒否。
- AI利用パスコード未入力時に説明を表示し、通常の記録は継続可能。
- オフライン中の記録と端末保存。
- 本番ビルド：サービスワーカーの有効化、PWAマニフェスト、192px/512pxアイコンの配信。ネットワークを切ってリロードしても食事が残り、追加記録後の再リロードでも保存を確認。
- iPhoneの上部余白をCSS変数で再現し、390px/320pxの画面、横向きの左右余白、通常ブラウザの余白ゼロで設定ボタンの位置・44px以上の操作領域・パスコード入力・体重ダイアログの位置を確認。実機固有のsafe-area値はiOSが提供する環境変数を使用。

## AIの検証範囲

Gemini RESTのリクエスト形式はGoogle公式ドキュメントで確認。APIの認証・検証・応答処理はテスト用のHTTP応答で確認。Vercel公開後、Gemini 3.5 Flash-Liteへの実接続を確認。食事の文章読み取りと腰への配慮を含む相談の両方がHTTP 200で応答。確認用の入力を使い、利用者の実記録は変更していない。AIが一般食品を表示値と判定する場合があったため、AI由来の値はサーバー側で推定として扱う。
