# Body Quest 初版の仕様

目的は七五三に向けた食事・運動の継続と、お腹・顔の見た目の改善。単独利用、iPhoneのPWA、追加費用を抑える。

## 実装する体験

- 5画面：今日、食事、運動、変化、コーチ。設定とバックアップは別画面。
- 食品プリセットを1タップで記録。量の変更、表示値の登録・修正、前日の食事をコピー。
- 材料の100gあたり栄養値と重量、完成後の重量、1食の重量から作り置きの栄養を計算。ご飯は別記録。
- ハイボールはウイスキー量、度数、杯数から純アルコールと熱量を計算。熱量にアルコールを含め、PFCには含めない。
- 朝・夜の体重、任意のウエスト。傾向は朝の7日平均を比較し、各週4日以上ある場合のみ助言。
- 家トレ・ジムのメニュー、痛みがある日の回復案。種目・時間・重量・セットなどを記録。
- 食事文章と写真のGemini読み取りは確認してから登録。献立・外食・体重推移の相談もGeminiに接続。
- 体の写真は端末内で比較。写真から体脂肪率や部分痩せを断定しない。

## 運用・境界

- Vite/React/TypeScript、Vercel Function。IndexedDBで端末内保存、JSONバックアップと検証付き復元。Supabase不要。
- 目標値は仮設定。医療者の指示を優先。LDL・腰への配慮は本人が設定。極端な制限・脱水・運動による罰を提案しない。
- 自炊週2回、外食を併用。職場の冷蔵庫・電子レンジなしを前提に、購入してすぐ食べる案。平日の予定は日ごとに変更可能。
- 一般食品・レシピの栄養は目安。チェーンの現行商品や公式値を捏造しない。公式表示を利用者が確認して登録する。
- APIキーはサーバーの環境変数。AIエンドポイントは個人用パスコードが必須。パスコードはsessionStorageに限定、バックアップに入れない。
- AIは明示送信時だけ利用し、送る文章・画像・最近の記録を画面で説明。体の経過写真は送信しない。
- 保存領域は公開URL/ブラウザに依存。SafariとPWAの共有は保証せず、ホーム画面追加後に使い始める。機種変更にはバックアップが必要。
- クラウド同期、バーコード食品DB、通知、体のAI分析は初版に含めない。

## 完了条件

食事と飲酒が日計に反映され、再読込でも残る。朝と夜を分離し平均を計算。作り置きの水分変化を完成重量で扱う。バックアップ書出し・復元が動作し不正データは拒否。ホーム画面追加とオフライン記録。AI設定なし・無料枠超過・不正応答で記録機能が失われない。
