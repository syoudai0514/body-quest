# Body Quest 初版の仕様

目的は利用者自身のイベント・長期目標に向けた食事・運動の継続。端末内の個人記録、iPhoneのPWA、追加費用を抑える。

## 実装する体験

- 5画面：今日、食事、運動、変化、コーチ。設定とバックアップは別画面。
- 食品プリセットを1タップで記録。量の変更、表示値の登録・修正、前日の食事をコピー。
- 材料の100gあたり栄養値と重量、完成後の重量、1食の重量から作り置きの栄養を計算。ご飯は別記録。
- ハイボールはウイスキー量、度数、杯数から純アルコールと熱量を計算。熱量にアルコールを含め、PFCには含めない。
- 朝・夜の体重、任意のウエスト。傾向は朝の7日平均を比較し、各週4日以上ある場合のみ助言。
- 家トレ・ジムのメニュー、痛みがある日の回復案。種目・時間・重量・セットなどを記録。
- 食事文章と写真のGemini読み取りは確認してから登録。献立・外食・体重推移の相談もGeminiに接続。
- 体の写真は端末内で比較。写真から体脂肪率や部分痩せを断定しない。

## 運用・境界

- Vite/React/TypeScript、Vercel Function。IndexedDBで端末内保存、JSONバックアップと検証付き復元。Supabase不要。
- 目標値は仮設定。医療者の指示を優先。LDL・腰への配慮は本人が設定。極端な制限・脱水・運動による罰を提案しない。
- 自炊週2回、外食を併用。職場の冷蔵庫・電子レンジなしを前提に、購入してすぐ食べる案。平日の予定は日ごとに変更可能。
- 一般食品・レシピの栄養は目安。チェーンの現行商品や公式値を捏造しない。公式表示を利用者が確認して登録する。
- APIキーはサーバーの環境変数。AI操作はパスワード入力不要。同一OriginのJSON送信と回数制限を適用。
- AIは明示送信時だけ利用し、送る文章・画像・最近の記録を画面で説明。体の経過写真は送信しない。
- 保存領域は公開URL/ブラウザに依存。SafariとPWAの共有は保証せず、ホーム画面追加後に使い始める。機種変更にはバックアップが必要。
- クラウド同期、バーコード食品DB、通知、体のAI分析は初版に含めない。

## 完了条件

食事と飲酒が日計に反映され、再読込でも残る。朝と夜を分離し平均を計算。作り置きの水分変化を完成重量で扱う。バックアップ書出し・復元が動作し不正データは拒否。ホーム画面追加とオフライン記録。AI設定なし・無料枠超過・不正応答で記録機能が失われない。


## 期限までのエネルギー計画
- 身長・年齢・開始/目標体重・活動量・任意の目標日を編集・保存。未入力のプロフィールは個人の仮値で埋めない。古い目標や記録を自動上書きしない。
- 開始日から期限前日まで。7700kcal/kgの粗いモデルで必要赤字を日・7日・合計表示。Mifflin–St Jeor式×活動係数＋運動の安静時との差分。運動込み係数では二重加算しない。
- 日・7日・14日・30日・期限の収支。食事・飲酒・運動の完了チェックがある日のみ比較。未記録・途中・未来日はゼロ摂取として判定しない。確定時の推定消費を保存。食事・運動変更で確定解除。
- 現在の食事目標と予定の追加運動で将来モデルを計算し、体重減に伴う基礎代謝低下を反映。実測の予測や達成保証とは区別。
- 朝15%・昼35%・夜40%・間食/飲酒10%の仮配分。大きい昼食の後は夕食候補量を調整。予算不足でも夕食抜きを提案しない。
- 月〜日の食事予算を再配分。過去の未確定日があれば保留。通常の自己管理用に採用しない低い配分は自動適用しない。
- Geminiに計算済みの目標・同一確定日数の不足・記録充足度・週予算を送信。届かない場合を明言し、極端な制限や過剰運動で補わせない。

## AIの利用
- パスワード入力・保持・認証ヘッダーを撤廃。Gemini APIキーはサーバーで管理。保存済みの旧パスコードは起動時に消去。
- サーバーは同じOriginからのapplication/jsonのPOSTを許可し、Sec-Fetch-Siteがあればsame-originを要求。Originの偽装が可能なHTTPクライアントに対する本人認証ではない。公開ページを使う利用者にもAIを提供する。
- 既存の入力/出力検証、タイムアウト、回数制限を適用する。

## 汎用目標・栄養計画の連携
- 共通フォームからプロフィール→イベント/長期目標→自動PFCを設定。3/6か月・1年後を選択可能。
- 自動モードは残り期間・朝の平均体重から更新。赤字は推定消費20%と体重0.75%/週の小さい方を上限とし、1,600kcal・基礎代謝を下回らない。極端な期限は達成できないことを表示する。
- Pは体重×1.2/1.6/2.0g（総カロリー30%上限）、Fは30%、Cは残り。運動記録の消費をそのまま食事へ上乗せしない。
- 過去の確定消費は変更しない。手動モードは自動更新しない。
- コーチの3強度、食品お気に入り、確定日の週間振り返り、食事CSV出力。API不要の機能は無料。
